# אתגר הסיום - מדריך התקנה והעלאה לאוויר

אתר ההרשמה והמעקב של "אתגר הסיום" (מרכז לאו), מסיום הש"ס (ב' בסיוון תשפ"ז) ועד חג השבועות תשפ"ז.
המדריך מיועד למפתח שיעלה את האתר. זמן משוער: חצי יום עבודה, לא כולל אישורים מול Meta (וואטסאפ), שיכולים לקחת כמה ימים.

## מה יש בחבילה

```
atgar-hasiyum/
├── firebase/                 ← זה מה שמעלים לאוויר
│   ├── public/               האתר עצמו (index.html, admin.html, privacy.html, assets/)
│   ├── functions/            קוד השרת: מונים, שגרירים, תזכורות, הסרה מרשימת תפוצה
│   ├── firestore.rules       הרשאות גישה למסד הנתונים
│   └── firebase.json
├── src/                      קוד המקור של האתר (עורכים כאן, ואז מריצים build.py)
├── build.py                  בונה את firebase/public מתוך src
└── dist/preview.html         גרסת הדגמה בקובץ אחד (בלי שרת)
```

**מה האתר עושה:** הרשמה עם Google, או הרשמה עצמית עם אימייל וסיסמה ואימות מייל, בחירת מסלול (זריעה / צמיחה / פסגה), תחום ויעד מתוך 54 אפשרויות או התחייבות אישית, פרטים אישיים ושדה "קהילה" שאינו חובה, הגדרת תזכורות (וואטסאפ / SMS / אימייל), שטר התחייבות, שיתוף וקישור שגריר אישי, אזור אישי עם מעקב התקדמות, מונה התחייבויות ציבורי, מונה לכל בית כנסת או ארגון, ולוח ניהול עם ייצוא ל-CSV.

**תזכורות:** נשלחות בשעה שהמשתתף בחר (08:00 / 13:00 / 20:30 שעון ישראל) ובתדירות שבחר. **לא נשלחות בשבת ובחג**: מיום שישי בשעה 12:00 עד מוצאי שבת, ומערב חג בשעה 12:00 (פסח, שביעי של פסח, שבועות). התזכורות נעצרות בערב שבועות. אם שליחה בוואטסאפ או ב-SMS נכשלת, ההודעה נשלחת במקומה באימייל.

## 1. דרישות מוקדמות

- Node.js 20 ו-Firebase CLI: `npm install -g firebase-tools`
- חשבון Google של הארגון. מומלץ חשבון ייעודי של מרכז לאו ולא חשבון פרטי.
- כרטיס אשראי לתוכנית Blaze של Firebase (תשלום לפי שימוש). התוכנית נדרשת לפונקציות שרת, לתזמון ולשליחת הודעות. בהיקפים קטנים העלות זניחה.

## 2. יצירת פרויקט Firebase

1. ב-[console.firebase.google.com](https://console.firebase.google.com) יוצרים פרויקט חדש, למשל `atgar-hasiyum`, ומשדרגים אותו ל-Blaze.
2. **Firestore Database** ← Create database ← מצב Production ← מיקום `me-west1` (תל אביב), או `europe-west1`.
3. **Authentication** ← Sign-in method:
   - להפעיל **Google**.
   - להפעיל **Email/Password** (הרשמה עצמית עם אימות מייל). אפשר להפעיל בתוכו גם את **Email link**.
   - **Templates** ← לשנות את שפת המיילים לעברית (Template language: Hebrew), את שם השולח ל"אתגר הסיום", ואם רוצים - את נוסח מייל האימות ומייל איפוס הסיסמה.
4. **Project settings** ← Your apps ← להוסיף Web app ← להעתיק את אובייקט `firebaseConfig`.
5. להדביק את הערכים בקובץ `firebase/public/config.js` (ובקובץ `src/config.example.js` אם רוצים שגם הבנייה הבאה תכיל אותם), ולעדכן את `siteUrl`.
6. בקובץ `firebase/.firebaserc` להחליף את `YOUR-PROJECT-ID` במזהה הפרויקט.

## 3. הגדרות שרת

```bash
cd firebase/functions
cp .env.example .env        # למלא את SITE_URL ואת MAIL_FROM
npm install
npm test                    # בדיקות לוגיקת התזמון וההודעות
```

**מפתחות סודיים.** כל ארבעת המפתחות חייבים להיות מוגדרים לפני העלאה. ספק שעוד לא חובר מקבל את הערך `none`:

```bash
firebase functions:secrets:set RESEND_API_KEY   # אימייל
firebase functions:secrets:set WA_TOKEN         # וואטסאפ
firebase functions:secrets:set TWILIO_SID       # SMS
firebase functions:secrets:set TWILIO_TOKEN     # SMS
```

## 4. ספקי הודעות

### אימייל - Resend (מומלץ להתחיל בו)
1. נרשמים ב-[resend.com](https://resend.com) ומאמתים את הדומיין שממנו יישלחו המיילים (רשומות DNS).
2. יוצרים API key ושומרים אותו ב-`RESEND_API_KEY`.
3. ממלאים בקובץ `.env` את `MAIL_FROM`, למשל `אתגר הסיום <reminders@your-domain.org.il>`.

### וואטסאפ - WhatsApp Business Cloud API (Meta)
1. Meta Business Manager של מרכז לאו ← אימות עסק ← WhatsApp ← הוספת מספר טלפון.
   **חשוב:** מספר שמחובר היום לאפליקציית וואטסאפ (למשל 058-5005531) לא יכול לפעול במקביל ב-Cloud API. מומלץ מספר ייעודי.
2. יוצרים **תבנית הודעה** בשם `atgar_hasiyum_reminder` בשפה עברית (`he`), עם 4 משתנים:
   ```
   שלום {{1}}, תזכורת מאתגר הסיום 🌿
   האתגר שלך: {{2}} - {{3}}% מהדרך.
   נשארו {{4}} ימים עד חג השבועות.
   לעדכון ההתקדמות ולהסרה מהתזכורות: https://YOUR-DOMAIN/#me
   ```
   (`{{1}}` שם פרטי, `{{2}}` ההתחייבות, `{{3}}` אחוז התקדמות, `{{4}}` ימים לשבועות.) Meta עשויה לסווג את התבנית כ-Marketing, וזה משפיע על המחיר לכל הודעה.
3. ממלאים את `WA_PHONE_ID` בקובץ `.env`, ואת ה-access token הקבוע (System User) ב-`WA_TOKEN`.
4. לגרסה האנגלית אפשר ליצור תבנית נוספת ולמלא את `WA_TEMPLATE_EN`.

### SMS - Twilio
ממלאים את `TWILIO_SID` ו-`TWILIO_TOKEN`, ובקובץ `.env` את `SMS_FROM` (מספר, או שם שולח אלפאנומרי). אפשר להחליף לספק ישראלי (019, InforU ודומיהם) על ידי שינוי הפונקציה `sendSms` בקובץ `functions/providers.js`.

## 5. העלאה לאוויר

```bash
cd firebase
firebase login
firebase deploy             # האתר, ההרשאות והפונקציות
```

אחרי ההעלאה האתר זמין בכתובת `https://PROJECT-ID.web.app`.

**הגדרת מנהלים:** ב-Firestore יוצרים אוסף בשם `admins`, ובו מסמך לכל מנהל. מזהה המסמך הוא כתובת האימייל המדויקת (באותיות קטנות), והתוכן לא משנה, למשל `{role: "admin"}`. לוח הניהול נמצא בכתובת `/admin`.

## 6. חיבור הדומיין הייחודי

1. Firebase ← Hosting ← **Add custom domain** ← מזינים את הדומיין ומוסיפים אצל רשם הדומיין את רשומות ה-DNS שמוצגות.
2. Authentication ← Settings ← **Authorized domains** ← מוסיפים את הדומיין.
3. מעדכנים את `siteUrl` בקובץ `public/config.js` ואת `SITE_URL` בקובץ `functions/.env`.
4. בנוסח תבנית הוואטסאפ מחליפים את הכתובת. שינוי בתבנית מחייב אישור מחדש של Meta.
5. מריצים שוב `firebase deploy`.

## 7. עריכת תכנים

כל הטקסטים (עברית ואנגלית) ותפריט 54 אפשרויות הלימוד נמצאים בקובץ `src/i18n.js`. מבנה הדף והעיצוב נמצאים ב-`src/page.html`, וההתנהגות ב-`src/app.js`.
אחרי שינוי מריצים `python3 build.py` מתיקיית השורש, ואז `firebase deploy --only hosting`.
טקסט התזכורות נמצא בקובץ `firebase/functions/messages.js`. אחרי שינוי מריצים `firebase deploy --only functions`.

## 8. קישורים לקהילות ולשגרירים

- **קישור לבית כנסת או ארגון:** `https://DOMAIN/?c=שם הקהילה`. השם מתמלא מראש בטופס, וכל ההתחייבויות נספרות יחד. בלוח הניהול יש מחולל קישורים.
- **קישור שגריר אישי:** `https://DOMAIN/?ref=קוד`. כל משתתף מקבל קישור כזה אחרי ההרשמה. המונה עולה כשמי שהוזמן מקבל על עצמו אתגר.

## 9. לפני ההשקה - רשימת בדיקה

- [ ] **מדיניות פרטיות** (`src/privacy.html`): הטיוטה צריכה בדיקה משפטית. שדה "קהילה" (חילונית / מסורתית / דתית-לאומית / חרדית) עשוי להיחשב **מידע בעל רגישות מיוחדת** לפי תיקון 13 לחוק הגנת הפרטיות. השדה הוא רשות, אבל צריך לוודא שהחובות הנלוות (אבטחה, יידוע, רישום מאגר אם נדרש) מטופלות.
- [ ] **קטינים:** בטופס יש קבוצת גיל "עד 17". צריך להחליט על מדיניות הסכמת הורים.
- [ ] **נוסח ההסכמה לקבלת הודעות** (חוק התקשורת, סעיף 30א) - הנוסח נמצא ב-`i18n.js` תחת `consent`. כל הודעה כוללת קישור הסרה.
- [ ] בדיקה במכשירים: אייפון ואנדרואיד, וגם פתיחה מתוך וואטסאפ ופייסבוק. בדפדפנים פנימיים של אפליקציות Google חוסמת התחברות, ולכן יש באתר גם הרשמה עם אימייל וסיסמה. מסד הנתונים מקבל כתיבה רק ממשתמשים שהאימייל שלהם אומת.
- [ ] שליחת תזכורת ניסיון לכל ערוץ: מגדירים למשתמש בדיקה ב-Firestore `nextAt` לזמן שעבר, ובתוך 15 דקות התזכורת נשלחת.
- [ ] Firebase ← App Check (reCAPTCHA) - הגנה מומלצת מפני הרשמות אוטומטיות.

## 10. היקף ועלויות

- **שרת ומסד נתונים:** עשרות אלפי משתתפים צפויים לעלות דולרים בודדים עד עשרות דולרים בחודש.
- **הודעות:** זו העלות העיקרית. וואטסאפ ו-SMS מחויבים לפי הודעה, אימייל כמעט בחינם. תזכורת יומית למאות אלפי משתתפים היא עלות משמעותית, ולכן כדאי לבדוק את התמחור מול Meta ומול ספק ה-SMS לפני ההשקה.
- **קצב שליחה:** הפונקציה שולחת כ-30,000 עד 40,000 תזכורות בכל ריצה (כל 15 דקות). אם יהיו יותר מ-50,000 תזכורות באותה שעה, למשל כולם ב-20:30, צריך להעביר את השליחה לתור (Cloud Tasks). זה שינוי מקומי בפונקציה `sendReminders`.

## מבנה הנתונים (לעיון)

| אוסף | תוכן | מי כותב |
|---|---|---|
| `users/{uid}` | שם, אימייל, פרטים, הגדרות תזכורת, הסכמה, קוד שגריר, מועד התזכורת הבאה | המשתתף (פרטים), השרת (קוד, מונים, תזמון) |
| `users/{uid}/commitments/{id}` | מסלול, תחום, יעד, התקדמות, הקדשה | המשתתף |
| `stats/global` | מונים: התחייבויות, נרשמים, לפי מסלול, תחום וקהילה | השרת בלבד, קריאה ציבורית |
| `communities/{key}` | מונה לכל בית כנסת או ארגון | השרת בלבד, קריאה ציבורית |
| `codes/{code}` | קוד שגריר ← משתמש | השרת בלבד |
| `admins/{email}` | רשימת מנהלים | ידנית בקונסולה |
